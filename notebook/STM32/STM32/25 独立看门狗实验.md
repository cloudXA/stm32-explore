### 核心代码

#### main.c 主函数

```c
int main(void)
{
  /* 初始化硬件 */
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_IWDG_Init();          // 初始化独立看门狗
  MX_USART1_UART_Init();

  /* USER CODE BEGIN 2 */
  HAL_UART_Transmit(&huart1, "program start\n", strlen("program start\n"), 100);
  /* USER CODE END 2 */

  /* 主循环 */
  while (1)
  {
    // 检测按键 KEY1 (PA0) 是否被按下
    if(HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
        HAL_IWDG_Refresh(&hiwdg);   // 喂狗：刷新看门狗计数器
        HAL_Delay(50);              // 按键消抖
    }
  }
}
```

#### 看门狗初始化 (iwdg.c)

```c
IWDG_HandleTypeDef hiwdg;

void MX_IWDG_Init(void)
{
  hiwdg.Instance = IWDG;
  hiwdg.Init.Prescaler = IWDG_PRESCALER_64;  // 预分频系数 64
  hiwdg.Init.Reload = 624;                   // (624 + 1) × 64 / 40kHz = 1s（标称）
  if (HAL_IWDG_Init(&hiwdg) != HAL_OK)
  {
    Error_Handler();
  }
}
```

### 代码逻辑说明

#### 1. 看门狗的作用

独立看门狗 (IWDG) 是一个倒计时计数器。程序必须在计数器减到 0 之前"喂狗"（刷新计数器），否则看门狗会认为程序跑飞，自动复位整个单片机。

```text
程序正常运行 → 定时喂狗 → 计数器被重置 → 不会复位
程序卡死/跑飞 → 没人喂狗 → 计数器减到 0 → 单片机复位
```

#### 2. 溢出时间计算

看门狗溢出时间由两个参数决定：

```text
溢出时间 = (预分频系数 / LSI频率) × (重装载值 + 1)
         = (64 / 40000) × (624 + 1)
         = 1.6ms × 625
         = 1000ms = 1秒
```

- **LSI 频率**：STM32F103计算时常用40kHz标称值，但实际误差较大
- **Prescaler = 64**：把 40kHz 分成 40000/64 = 625Hz，即每个计数 1.6ms
- **Reload = 624**：从624到0共625个计数 × 1.6ms = 1秒（按40kHz标称值）

所以：**1 秒内不喂狗，单片机就会复位**。

#### 3. 喂狗逻辑

```c
if(HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
    HAL_IWDG_Refresh(&hiwdg);   // 按下按键才喂狗
    HAL_Delay(50);              // 消抖，防止一次按键触发多次
}
```

- `GPIO_PIN_RESET` 表示按键按下（低电平有效，PA0 默认上拉）
- 按下 KEY1 → 喂一次狗 → 计数器重新加载为624
- `HAL_Delay(50)` 用于按键消抖

**实验现象**：
- 一直按着 KEY1 → 持续喂狗 → 程序不会复位
- 松开 KEY1，超过 1 秒不喂狗 → 看门狗复位 → 串口重新打印 "program start"

#### 4. 为什么用独立看门狗 (IWDG)

| 特性 | 独立看门狗 (IWDG) |
|------|------------------|
| 时钟源 | LSI（内部 40kHz，独立于主时钟） |
| 独立性 | 即使主时钟/系统时钟故障也能工作 |
| 一旦开启 | 无法软件关闭，只能复位后关闭 |
| 适用场景 | 检测程序跑飞、死循环等严重故障 |

独立看门狗由独立的 LSI 时钟驱动，不受主系统时钟影响。即使程序因为时钟配置错误或死循环而完全失控，看门狗仍然能正常倒计时并在超时后复位系统，是单片机"最后一道保险"。

## ------------------------------------------------------------------------------

“独立看门狗”可以理解成STM32内部一个使用独立时钟工作的倒计时复位器：

> 程序必须定期告诉它“我还活着”；如果超过规定时间没有报告，它就认为程序卡死，强制复位STM32。

它的英文是 `Independent Watchdog，IWDG`。

## 为什么叫“独立”

这里的“独立”主要是指它使用独立的低速内部时钟 `LSI`，不依赖CPU主时钟。

```text
CPU和程序使用：
HSE/HSI → PLL → 系统时钟

独立看门狗使用：
LSI低速内部时钟
```

即使出现以下情况：

- 主程序卡死；
- 系统时钟配置异常；
- 程序进入死循环；
- 某个任务长期阻塞；

IWDG仍然可以用自己的LSI时钟继续倒计时，并最终复位MCU。

因此它像一个拥有独立手表的监督员，不需要询问CPU现在几点。

## 它怎么工作

IWDG内部可以简化成：

```text
LSI时钟
   ↓
预分频器PSC：让计数速度变慢
   ↓
递减计数器
   ↓
从RLR设定值不断减到0
   ↓
STM32复位
```

启动时，把计数器装入一个初始值，例如：

```text
RLR = 624
```

随后计数器递减：

```text
624 → 623 → 622 → …… → 1 → 0
```

如果到0之前执行喂狗：

```c
HAL_IWDG_Refresh(&hiwdg);
```

计数器会重新加载为624：

```text
剩余238
  ↓ 喂狗
重新变成624
```

只要一直在超时前喂狗，就不会复位。

## 图片中的1秒怎么算

超时时间可以近似理解为：

```text
超时时间 = 预分频系数 × 重装载计数值 ÷ LSI频率
```

图片中：

```text
PSC = 64
RLR = 624
LSI ≈ 40,000Hz
```

代入：

```text
T = 64 × (624 + 1) ÷ 40,000
  = 1秒
```

也就是：

```text
一个计数周期 = 64 ÷ 40000
             = 0.0016秒
             = 1.6ms

625次 × 1.6ms
= 1000ms
= 1秒
```

因此，如果大约1秒内没有喂狗，STM32就会复位。

更严谨的公式有时写成：

```text
T = Prescaler × (Reload + 1) ÷ LSI
```

对STM32F103的IWDG，按寄存器计数规则应使用 `RLR + 1`。教程把RLR直接当作计数次数属于近似写法；即使寄存器算得精确，LSI自身误差仍会让实际时间偏离1秒，产品中应测量并留安全余量。

## 图片中的实验要做什么

要求是：

```text
开启独立看门狗
溢出时间约1秒
按键1用于喂狗
```

程序大概是：

```c
while (1)
{
    if (检测到按键1按下)
    {
        HAL_IWDG_Refresh(&hiwdg);
    }
}
```

现象是：

### 不按按键

```text
程序启动
→ IWDG开始倒计时
→ 1秒内没有喂狗
→ 计数到0
→ STM32复位
→ 程序重新启动
→ 再次开始倒计时
```

可以在程序启动时翻转或点亮LED，用LED现象观察MCU正在反复复位。

### 不断按按键

```text
程序启动
→ 在1秒内按键
→ 喂狗，重新加载为624
→ 又在1秒内按键
→ 再次加载为624
→ 程序不复位
```

这个实验是在证明：

> 喂狗可以延长运行；停止喂狗后，硬件会自动复位。

## 和窗口看门狗的区别

独立看门狗的规则比较简单：

```text
只要别太晚喂就行
```

例如超时时间为1秒：

```text
第100ms喂：可以
第300ms喂：可以
第900ms喂：可以
超过约1秒：复位
```

窗口看门狗则是：

```text
太早喂不行
规定窗口内喂才可以
太晚喂也不行
```

| 特点 | IWDG独立看门狗 | WWDG窗口看门狗 |
|---|---|---|
| 时钟 | 独立LSI | APB总线时钟 |
| 喂得太早 | 可以 | 可能复位 |
| 喂得太晚 | 复位 | 复位 |
| 主要检测 | 程序停止运行 | 程序过慢或运行节奏异常 |
| 使用难度 | 较低 | 较高 |
| 常见程度 | 更常用 | 特定场景使用 |

## 真正项目里怎么用

假设你的ESP8266程序正常时，主循环持续工作：

```c
while (1)
{
    ESP_ProcessReceive();
    ESP_ProcessConnection();
    LED_ProcessPending();

    HAL_IWDG_Refresh(&hiwdg);
}
```

如果程序卡死在某处：

```c
while (!WIFI_GOT_IP_Flag)
{
    /* 没有超时，永远出不来 */
}
```

后面的喂狗代码无法执行：

```text
超过IWDG超时时间
→ STM32复位
→ ESP8266重新初始化
→ 系统尝试恢复
```

但正式项目不能只是无条件喂狗：

```c
while (1)
{
    HAL_IWDG_Refresh(&hiwdg);
}
```

更合理的是先做健康检查：

```c
if (uart_task_ok &&
    network_task_ok &&
    sensor_task_ok)
{
    HAL_IWDG_Refresh(&hiwdg);
}
```

只有所有关键部分都正常，才允许喂狗。

## IWDG的重要限制

在很多STM32上，一旦软件启动IWDG，就不能通过普通代码将它关闭，只能依靠复位重新开始。

因此启动前必须确保：

- 初始化过程不会超过超时时间；
- 所有长时间等待都有机会喂狗，或者设置足够长的超时；
- 下载调试时看门狗可能继续运行；
- 断点暂停CPU后，看门狗可能导致复位，除非配置调试冻结。

初学实验中如果发现：

```text
程序一打断点就不断复位
```

不一定是代码坏了，可能是CPU停在断点，而独立看门狗仍在倒计时。

## 最简单的记忆方式

```text
IWDG：
有最晚期限，没有最早限制
独立时钟，超时复位

WWDG：
既有最早时间，也有最晚时间
必须在规定窗口内喂狗
```

图片里的实验本质上就是：

> 给程序一个约1秒的生命倒计时；每次按键相当于把生命值恢复为1秒，如果一直不按，STM32就自动复位。

## 按键电平也要以原理图为准

示例用 `GPIO_PIN_RESET` 表示按下，只在按键低电平有效并且PA0空闲时被上拉的电路中成立。有些开发板PA0按下反而是高电平。实验前应读取原理图或串口打印实测值，不能把“按下=低”当成所有板卡通用规则。

## 判断本次是不是看门狗复位

程序上电后可以读取RCC复位标志，记录启动原因，再清除标志：

```c
if (__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST) != RESET)
{
    /* 上一次复位由IWDG引起 */
}

__HAL_RCC_CLEAR_RESET_FLAGS();
```

具体宏名以当前STM32F1 HAL头文件为准。这样比只看“program start”更能区分看门狗复位、上电复位和手动复位。

## 正式项目的喂狗原则

不要只要主循环还能转就无条件喂狗。应让UART、网络、传感器等关键模块各自上报健康状态，只有它们在规定周期内都完成关键工作时才刷新IWDG。超时时间还必须覆盖最坏情况下的启动、Flash擦写和网络恢复时间，并保留余量。
