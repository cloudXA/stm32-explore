# STM32 串口中断接收 Q&A 笔记

## 1. UART_RX_BUF 数组定义

```c
uint8_t UART_RX_BUF[UART_RX_BUF_LEN]; /* 接收缓冲区 */
```

| 部分 | 含义 |
|------|------|
| `uint8_t` | 每个元素是 8 位无符号整数（0~255），占 1 字节 |
| `UART_RX_BUF` | 数组名 |
| `[UART_RX_BUF_LEN]` | 数组长度 = 64 |

总共 64 字节，刚好用来存从串口收到的字符（每个字符 1 字节）。

---

## 2. UART_RX_STA 的 volatile 和用途

```c
volatile uint16_t UART_RX_STA = 0; /* bit15=完成, bit14-0=已收字节数 */
```

### 为什么有 volatile？

因为这个变量**在中断和主循环之间共享**：

| 谁在写 | 谁在读 |
|--------|--------|
| 中断回调 `HAL_UART_RxCpltCallback` | 主循环 `while(1)` |

中断随时可能触发并修改 `UART_RX_STA`。如果不用 `volatile`，编译器优化时可能会把值缓存到寄存器里，主循环每次都读寄存器里的旧值，永远看不到中断的更新。

> `volatile` = "别优化我，每次都从内存读最新值"。

### 这个变量干什么的？

一个变量同时存两种信息：

```
bit15              bit14~bit0
  ↓                    ↓
接收完成了吗？      收到几个字节了？
```

**中断和主循环之间的传话筒**：中断负责写，主循环负责读。

---

## 3. HAL_UART_Receive_IT 的参数

```c
HAL_UART_Receive_IT(&huart1, &UART_RX_BUF[0], 1);
//                   ↑          ↑              ↑
//               用哪个串口   数据存到哪     收几个字节
```

| 参数 | 值 | 含义 |
|------|-----|------|
| `&huart1` | USART1 的句柄地址 | 告诉 HAL 用 USART1 |
| `&UART_RX_BUF[0]` | 数组第一个元素的地址 | 收到的字节写到 `UART_RX_BUF[0]` |
| `1` | 1 个字节 | 收满 1 个字节就触发回调 |

`&UART_RX_BUF[0]` 就是数组的起始地址，等价于直接写 `UART_RX_BUF`。

---

## 4. 收到 'o' 时回调的执行过程

```
上电后 UART_RX_STA = 0

收到第一个字节 'o' → 触发中断 → 进入回调
  ↓
uint16_t idx = 0 & 0x3FFF = 0
  ↓
UART_RX_BUF[0] = 'o'，不是 \r 也不是 \n → 跳过换行判断
  ↓
idx++ → idx = 1
  ↓
UART_RX_STA = 1
  ↓
HAL_UART_Receive_IT(&huart1, &UART_RX_BUF[1], 1)  ← 下一个字节存到 BUF[1]
```

---

## 5. 完整接收 'open\n' 的过程

```
第1次中断（收到 'o'）：
  idx = 0, UART_RX_BUF[0] = 'o'，不等于 \r/\n → 跳过
  idx++ → idx = 1, UART_RX_STA = 1
  HAL_UART_Receive_IT(&huart1, &UART_RX_BUF[1], 1)  ← 准备收下一个到 BUF[1]

第2次中断（收到 'p'）：
  idx = 1, UART_RX_BUF[1] = 'p' → 跳过
  idx++ → idx = 2, UART_RX_STA = 2

第3次中断（收到 'e'）：
  idx = 2, UART_RX_BUF[2] = 'e' → 跳过
  idx++ → idx = 3, UART_RX_STA = 3

第4次中断（收到 'n'）：
  idx = 3, UART_RX_BUF[3] = 'n' → 跳过
  idx++ → idx = 4, UART_RX_STA = 4

第5次中断（收到 '\n'）：
  idx = 4, UART_RX_BUF[4] = '\n' → 命中！
  UART_RX_STA = 4 | 0x8000 = 0x8004
  return（不再调 HAL_UART_Receive_IT，等主循环处理）
```

就像一个流水线：每次中断收 1 个字节、指针往后挪一格、继续等下一个，直到遇见 `\n` 才停。

---

## 6. UART_RX_STA = 4 | 0x8000 干了什么

```
4      = 0000 0000 0000 0100
0x8000 = 1000 0000 0000 0000
         ───────────────────
按位或   = 1000 0000 0000 0100
        = 0x8004
```

就是给 `UART_RX_STA` 同时打上两个标记：**完成了** + **长度是 4**。

### main 一直在跑，为什么不会错过？

```
时间线：
─────────────────────────────────────────────────────────→

中断收 o   中断收 p   中断收 e   中断收 n   中断收 \n
  ↓          ↓          ↓          ↓          ↓
UART_RX_STA=1  =2        =3         =4       =0x8004
                                               ↓
                                        main 循环刚好跑到
                                        if (UART_RX_STA & 0x8000)
                                        一看：0x8004 & 0x8000 ≠ 0
                                        → 进入处理！
```

在收 `\n` 之前，bit15 始终是 0，main 每轮检查都是 0，跳过不处理。直到 `\n` 把 bit15 置 1，main 下一轮才发现并进入处理。

## 7. UART_RX_BUF[len] = '\0' 的作用

C 语言里**数组本身不是字符串**，只有用 `\0` 结尾的字符数组才算字符串。

```
之前（不是字符串）：                   之后（是字符串）：
┌───┬───┬───┬───┬────┬─────┐        ┌───┬───┬───┬───┬────┬─────┐
│ o │ p │ e │ n │ \n │ ... │        │ o │ p │ e │ n │ \0 │ ... │
└───┴───┴───┴───┴────┴─────┘        └───┴───┴───┴───┴────┴─────┘
  ↑                         ↑          ↑               ↑
 首地址                   没有结束符     首地址          结束符
```

`\0` 是 C 字符串的"句号"，`strcmp` 读到 `\0` 就停。

---

## 8. 为什么用 strcmp 而不用 ==？

C 语言**不能用 `==` 比较字符串**：

```c
// ❌ 这样比的是地址，不是内容
if (UART_RX_BUF == "open")

// ✅ 这样才比内容
if (strcmp((char *)UART_RX_BUF, "open") == 0)
```

`UART_RX_BUF` 是数组名，本质是一个**内存地址**。`"open"` 是存在代码区另一个地址的常量。`==` 比的是两个地址是否相同，永远是 false。

`strcmp` 做的事是**逐字节比较两个字符串的内容**：

```
UART_RX_BUF → [o][p][e][n][\0]
"open"      → [o][p][e][n][\0]

逐字节比较：o==o ✅  p==p ✅  e==e ✅  n==n ✅  都相等 → 返回 0
```

> 记成：`strcmp` 返回 0 表示"比较结果没有差异"，就是相等。

---

## JS vs C 对比

```js
// JS：直接用 ===
if (str === "open") { ... }

// C：必须用 strcmp
if (strcmp(str, "open") == 0) { ... }
```

```js
// JS 字符串天然带长度，不需要结束符
const buf = ['o','p','e','n'];
const str = buf.join('');  // "open"

// C 数组需要手动加 \0 才变成字符串
UART_RX_BUF[4] = '\0';  // 现在才是 "open"
```
